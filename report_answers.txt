2. HONEYPOT SERVICES
--------------------
An actual local service check sent 20 connections: 10 TCP logins and
10 HTTP login POSTs. The services bound to 127.0.0.1 on ephemeral test ports.
The database recorded 20 sessions and 40 events: 10 tcp_connection,
10 tcp_login_attempt, 10 http_request, and 10 http_login_attempt rows.
Events logged versus events expected: 40/40. Password contents were not
stored; only lengths were recorded. The simulator also connected from the
three loopback aliases; the listeners remained bound only to 127.0.0.1.
Configured default listener addresses are 127.0.0.1:8022 (TCP) and
127.0.0.1:8081 (web).

Observed malformed/large/disconnected input behavior:
- Invalid UTF-8 TCP username: service replied "Invalid input." and saved a
  tcp_protocol_error event.
- 600-byte TCP line: service replied "Invalid input." and saved a
  tcp_protocol_error event. The configured line limit is 512 bytes.
- Client disconnect during a TCP prompt: service logged tcp_disconnect and
  continued running.
- Malformed web form bytes: returned the fake login-failure page and logged
  the request and attempt.
- 17,000-byte web body: returned HTTP 413 and logged the request.
- Submitted inputs were treated as data; none were executed.

3. FEATURES
-----------
Feature computation and purpose:
- event_count: count of events for the session; overall activity volume.
- tcp_connection_count: count of tcp_connection events; TCP engagement.
- http_request_count: count of http_request events; web interaction volume.
- login_attempt_count: TCP plus HTTP login attempts; guessing intensity.
- unique_usernames: distinct attempted usernames in the session.
- unique_paths: distinct HTTP paths in the session.
- session_duration_seconds: last event minus first session/event time.
- attempts_per_minute: login attempts * 60 / max(duration seconds, 1).
- payload_length_chars: username length plus password length plus HTTP path
  length; password contents are not stored.
- error_count: tcp_protocol_error plus http_error events.
- error_ratio: error_count / event_count, or 0 when there are no events.
- unique_event_types: number of distinct event types in the session.
- source_attempts_60s: login attempts for the same source in the trailing
  60-second window ending at that session's final event.
- source_distinct_usernames_60s: distinct attempted usernames for that source
  in the same trailing window.
- source_request_rate_per_second_60s: TCP connections plus HTTP requests for
  that source in the window, divided by 60 seconds.

10. LIMITATIONS
---------------
- All training and evaluation data is synthetic, generated from bounded
  templates and short vocabularies; it does not represent real attacker
  diversity or behavior.
- Low-and-slow pacing and benign typos/long inputs are configured synthetic
  patterns, not observed human or attacker behavior.
- All three source addresses are loopback aliases on one computer, not
  independent hosts or network paths.
- Services intentionally bind to 127.0.0.1, always reject credentials, and
  the web service uses Flask's development server.
- Source-window features depend on the synthetic source assignment and event
  order. The random session-level train/test split does not group sessions by
  source or time, so related source-window values can occur across splits and
  the reported scores may overstate performance on independent sources.
- Test-split mistakes were limited to benign versus SQL injection; on the
  different-seed set, the same pair accounted for all errors. The experiment
  does not establish real-world generalization.
- The clean empty-database pipeline had one SQL-injection-labeled session
  predicted benign. In a populated experiment database, source-window history
  differs; the two runs are not directly interchangeable.
- Database timestamps have millisecond resolution, not packet-level timing.
- Throughput tests were sequential; saturation behavior was not measured.
- The current verified interpreter was Python 3.14.5; other Python versions
  were not tested.
