2. HONEYPOT SERVICES
--------------------
The services were started for an actual 20-connection localhost check:
10 TCP login attempts and 10 HTTP login POSTs. Both bound to 127.0.0.1
(ephemeral test ports). The test produced 20 sessions and 40 events:
10 tcp_connection, 10 tcp_login_attempt, 10 http_request, and
10 http_login_attempt rows. Thus each of the 20 login connections had the
expected connection/request row and login-attempt row. Password contents
were not persisted; only password lengths were stored.

Observed bad-input behavior:
- Invalid UTF-8 TCP username: replied "Invalid input."; logged
  tcp_protocol_error.
- 600-byte TCP line: replied "Invalid input."; logged tcp_protocol_error.
- Client disconnect after TCP prompt: connection closed; logged
  tcp_disconnect.
- Malformed web form bytes: returned HTTP 200 with the fake "Login failed"
  page; logged the request and a login attempt.
- 17,000-byte web body: returned HTTP 413; the incoming request was logged.
- Service ports are validated before binding. The production/default service
  addresses in the code are 127.0.0.1:8022 (TCP) and 127.0.0.1:8081 (web).

3. FEATURES
-----------
Feature purpose and computation:
- event_count: count of session events; activity volume.
- tcp_connection_count: count of tcp_connection rows; TCP engagement.
- http_request_count: count of http_request rows; web probing/browsing.
- login_attempt_count: count of TCP and HTTP login-attempt rows; credential
  guessing intensity.
- unique_usernames: distinct logged usernames; credential breadth.
- unique_paths: distinct requested paths; path discovery breadth.
- session_duration_seconds: last event minus first session timestamp; activity
  span (timestamps have one-second resolution).
- attempts_per_minute: login attempts * 60 / max(duration seconds, 1);
  duration normalization without division by zero.
- payload_length_chars: sum of username length, password length, and HTTP path
  length; coarse input size without storing passwords.
- error_count: count of tcp_protocol_error and http_error rows.
- error_ratio: error_count / event_count, or 0 for no events.
- unique_event_types: distinct event types; interaction variety.

10. LIMITATIONS
---------------
- All attack data is synthetic, bounded, and generated from a small set of
  scenario templates; the credentials, SQL probes, and directory paths are
  short fixed lists, and port probing checks only known service ports. This
  does not capture the variety of real attackers.
- Services intentionally bind only to 127.0.0.1 and the web endpoint uses the
  Flask development server; this is not a remotely deployable service.
- Both fake login services always reject credentials; password contents are
  not stored, and successful authentication is not modeled.
- The integration runner uses deterministic event heuristics and does not
  load the saved Random Forest. Model evaluation is a separate command.
- Model training uses only 50 synthetic sessions; the additional 50-session
  seed check does not establish real-world generalization.
- SQLite stores timestamps with one-second resolution; short durations can
  appear as zero seconds.
- `.env` files are not loaded by the application, and the standalone
  `config/settings.yaml` validator is not wired into service launch commands.
- The reported run used Python 3.14.5; other interpreter versions were not
  tested in this environment.
- The observed test set is small: only 13 sessions. Error-rate estimates and
  feature importances are consequently unstable.
- The measured throughput tests were sequential and bounded. No saturation
  limit was measured.
